# KAGARI（篝）0.9.2
Windows 11 x64 用のデスクトップアプリです。メイン画面はWPF、タスク・履歴・実行処理はRustです。ZIPを展開し KAGARI.exe を起動してください。

1. 「＋ プロジェクト」で既存フォルダーを選択。左のツリーで登録済みプロジェクトを選択します。左右キーで展開・折りたたみ、上下キーで選択できます。フォルダーは展開時に読み込みます。Markdownファイルを選ぶと資料欄に表示します。資料タブで「登録」を押すと関連付けます。「更新」でツリーを再読み込みします。
2. 「新規」でタスク名、担当、状態、期限、次回確認を入力して「保存」。タスクは選択中のプロジェクトに登録されます。登録データは %LOCALAPPDATA%\RustAIWorkspace\workspace.tsv に保存します。
3. 資料欄のタブ（仕様書・作業ログ・結果）を選び、左ツリーでMarkdownを選択して「登録」を押します。UTF-8の見出し・箇条書き・チェックリスト・コードブロックに対応。更新後は「再表示」で再読込します。
4. 作業キューでタスクを選び、状態ボタンで進行を更新するか「AIに依頼」を選択します。依頼モーダルでCodex／Claude Codeとモデルを選択し、タスク名から初期入力された依頼を確認して「実行」。モデル候補はCLI既定、代表モデル、手入力に対応します。選択モデルは利用中の認証・契約で利用できるものを指定してください。利用するCLIにログインしてください。PATH、ユーザーの標準インストール先、対応するVS Code拡張の順に実行ファイルを検索します。 Codexデスクトップ同梱版のWindowsランナーが起動しない場合は、KAGARI専用CLIを PowerShell で `npm.cmd install --prefix "$env:LOCALAPPDATA\RustAIWorkspace\cli" @openai/codex@0.171.0` として配置できます。専用CLIがあればデスクトップ同梱版・VS Code拡張より優先します。
5. 「Git差分」は選択プロジェクトの変更状況とステージ前後の差分を表示します。Git for Windowsが必要です。
6. 一覧の操作ボタンで作業開始・確認待ち・完了を切り替えます。今週の完了率は月曜から日曜に期限があるタスクの完了件数／総数です。確認待ちと期限超過は全期間が対象です。プロジェクト・担当AIの絞り込みはタスクとKPIの両方に反映されます。
7. 「共有目標・進捗」に既存ダッシュボードの閲覧用合言葉を入力すると、共有目標・達成度・作業・課題をアプリ内で取得します。合言葉は終了時までメモリ内に保持します。共有側の情報は読み取り専用です。「SHIRANUI ログ」は指定したUTF-8テキストログの末尾64 KiBを表示します。サイドバーの「SHIRANUI」で監視サービスの状態とアラート履歴を確認できます。「アラート判断」タブでは対象を選んで「問題なし」「要確認」または「判断を取り消す」を送信できます。送信にはSHIRANUIの受付フォルダーへの書き込み権限が必要です。

## メール・Slack の連絡をタスクに取り込む

Node.js 22 以降とローカルの stdio MCP クライアントを使います。クライアントに次のサーバーを登録してください。スクリプトの次の引数は KAGARI で登録済みの既定プロジェクトです。配置先が異なる場合はパスを変更してください。

```json
{
  "mcpServers": {
    "kagari": {
      "command": "node",
      "args": [
        "D:/.company/os/kagari/mcp/import-message.mjs",
        "D:/.company/os/kagari"
      ]
    }
  }
}
```

同じクライアントでメールや Slack のコネクタを接続し、例えば「この Slack 投稿を kagari のタスクにして」と依頼します。コネクタが選択した連絡を読み、`import_message` に取得元、アカウントまたはワークスペース／チャンネル、個別メッセージ ID、題名、具体的な作業内容、任意の元リンクを渡します。メールでは毎回同じアカウント識別子とメッセージ ID を、Slack では投稿自身の ts を文字列で渡してください。

### 差出元・内容によるプロジェクトの振り分け

KAGARI の左ツリーで、MCP の起動引数に指定したプロジェクトを右クリックし「外部連絡の取込設定…」を開きます。既定の登録先を選び、「追加」でサービス・差出人・キーワード・登録先を入力してください。「上へ」「下へ」で優先順位を変更できます。「保存」すると次回の取込から反映されます。この機能の追加前から起動中の MCP は、初回のみ再起動してください。

以前の構成で `args` の末尾に JSON ファイルを指定している場合、初回保存前に「旧ルールを追加…」でそのファイルを選ぶと引き継げます。保存後は接続元プロジェクトごとの画面設定を優先します。保存前は従来どおり引数のファイルを使用します。旧ルールファイルの例を以下に示します。

```json
[
  {"source": "gmail", "sender": "orders@example.com", "contains": "見積", "project": "D:/projects/営業"},
  {"source": "slack", "sender": "U0123456789", "project": "D:/projects/制作"},
  {"contains": "障害報告", "project": "D:/projects/保守"}
]
```

各ルールには `sender`（メールアドレスまたは Slack ユーザー ID の完全一致）、`contains`（元の件名・本文・タスク名・作業内容のいずれかに含む文字列）の片方または両方を指定します。`source` でサービスも限定できます。英字の大小は区別せず、指定した条件をすべて満たす最初のルールを採用します。コネクタからは取得できた差出人・元の件名・本文を `sender`・`subject`・`body` で渡してください。元の本文は判定だけに使います。

一致するルールがなければ既定プロジェクトに登録します。設定を読めない場合、形式が不正な場合、選ばれたプロジェクトが未登録の場合はエラーになります。受付結果の `project` に実際の振り分け先が返ります。同じ既定プロジェクトで受け付けた連絡を再取込しても、ルール変更による二重登録や移動は起きません。

`queued` は受付済み、`already_queued` は同じ連絡が受付待ち、`processed` は KAGARI が処理済みです。KAGARI の起動時または稼働中のキュー読込後、作業キューで未着手タスクと「次の作業」の出典を確認できます。ファイルキューにはハードリンクを利用できるローカルボリューム（NTFS など）が必要です。

## ソースからビルド
Rust stable x86_64-pc-windows-msvc、Visual Studio C++ Build Tools、Windows 10 SDKを使用。build-ui.ps1 を実行すると、RustコアとWPF画面の両方をビルドします。UIにはWindowsの.NET Framework 4.xを使います。外部Rustクレートは不要です。

一覧はピン留めを先頭とし、各グループ内は期限超過、本日期限、確認待ち、3日以内の期限、作業中、通常、完了の順に並びます。同順位は期限順です。矢印キーで行を選ぶと詳細と文書が切り替わります。ウィンドウは最大化・サイズ変更できます。旧版を終了してから起動すると既存のタスクを読み込みます。

「やりたいこと」は候補から選ぶか自由入力し、保存します。空欄で保存すると「進捗を確認」で登録します。期限は今日・明日ボタンで設定できます。KPIボタンで現在のプロジェクトのタスクを抽出します。週の達成率はプロジェクト・担当の絞り込みを反映します。ピン留めは再起動後も有効です。
プロジェクト別の円グラフでは、未着手で登録されたタスクのうち、直近のKAGARI依頼に正常な回答があり、実行中の依頼がないものを「次の作業依頼待ち」として集計します。グラフをクリックすると、そのプロジェクトの作業キューが開きます。右クリックで開く状態推移は、記録済みのタスク状態に基づき、未着手と次の作業依頼待ちの合計を表示します。

作業キューの＋で新規作成。既存タスクはダブルクリック、Enterまたは「詳細を開く」で編集します。「保存してAIに依頼」で編集内容を保存してモデル選択に進みます。キャンセルまたはEscで閉じます。アイコンはマウスを重ねると操作名を表示し、Tabで選ぶと右上に操作名を表示します。
AI実行は非対話型です。Codexは exec、Claude Codeは -p を使い、CLIの通常の権限設定に従います。Claude CodeがBash・PowerShellコマンドの承認を求めると、作業キュー下部の「コマンドの承認待ち」に要求が表示されます。［今回だけ許可］か［拒否］を選べます。実行先とコマンドは［詳細を表示］で確認できます。同じ依頼の同じ実行先・コマンド・オプションは許可を再利用します。サブエージェント、バックグラウンド実行、サンドボックス解除の要求は個別に確認します。モーダルを閉じても開始済みの処理は継続します。

直近5件の日時・担当AI・指定モデル・依頼（360文字）・回答（650文字）を表示します。「直近のやり取りを依頼に含める」を選ぶと、直近5件中の完了した依頼と回答の抜粋も選択したAIに渡します。元の依頼・回答は %LOCALAPPDATA%\RustAIWorkspace\history 以下に保存します。KAGARI v0.7以降の依頼が対象です。既存タスクにも初回依頼時に履歴IDを発行します。

Ctrl＋Fでタスク検索、検索欄のEscで検索語を消せます。「絞り込みを解除」で検索・担当・KPIの条件をまとめて解除します。作業キューの状態ボタンには、選択したタスクの次の操作を表示します。

タスク詳細の「継続・完了を依頼」（Alt＋J）を押すと、残作業があれば継続し、すべて終わっていればステータスを「完了」にするよう求める依頼文が下書きの末尾に入ります。内容を確認・編集して「依頼を送信」を押してください。

## レイアウト
左サイドバーの3列アイコンで、エクスプローラー・作業キュー・タスク資料を左から1:1:2に配置します。初期配置も同じです。ドラッグ後も押し直すと幅が戻り、プロジェクト別KPIの表示設定は保持されます。
上部のペインアイコンでプロジェクト、プロジェクト別の進捗、作業キュー、タスク資料を個別に切り替えます。境界線はドラッグで調整できます。「左右に分割」「上下に分割」はキューと資料に適用します。設定は次回起動時に復元します。「標準に戻す」で全ペインを表示します。

## セッション履歴

### 画面を操作せずタスクの状態を更新する

KAGARI の配布フォルダーで `./Set-TaskStatus.ps1 -TaskId <32桁のタスクID> -Status done` を実行できます。状態名は `todo`、`working`、`review`、`done` です。IDは workspace.tsv の T 行に保存したタスクIDです。AIの回答到着だけで作業を完了にすることはありません。

起動中は作業キューの更新処理、終了中は同じ保存処理を使います。結果が `saved` なら保存と読み戻しが完了しています。`queued` は受付済みで、指定された Receipt ファイルに処理結果が残ります。編集ダイアログを開いている間などは反映が遅れることがあります。受付後に他の操作で別の状態になった場合は `rejected` が記録されます。
移行済みのゲーム案件は、エクスプローラーで `chromarch` を選ぶと `.company\dots\game_creator\TurfWars` が開きます。旧フォルダー `.company\game_creator\TurfWars` の履歴や資料リンクも、この作業先に対応します。共有フォルダーの履歴には、依頼やタイトルの先頭が `chromarch` または `TurfWars` のものも表示されます。

AIへの依頼は、実行プロセスが生存している間は出力間隔が長くても「実行中」と表示されます。コマンドの許可が必要な間は「承認待ち」、回答を受け取る前にプロセスが終了した場合は「中断」と表示されます。最後に受信したツール結果は状態の詳細で確認できます。中断した依頼はタスクの「設定・履歴」で途中結果の抜粋と保存先を確認できます。保存先の `request.md` は元の依頼、`prompt.txt` は送信する入力本文、`partial.txt` は受信済みの途中結果です。添付画像は同じ依頼の `images` に保存します。

左の時計アイコン、または実行 → セッション履歴で、WindowsユーザーのCodex・Claude Code CLIの最近のローカル履歴を最大160ファイルから読み込みます。会話を選んで「タスクに登録」、または「登録して再開」でモデルと依頼を確認して実行します。同じプロジェクト・担当AI・セッションIDの登録は既存タスクを開きます。再開には元のフォルダーとCLI履歴が必要です。ChatGPTのウェブ履歴は対象外です。

## KAGARI自身の改善
実行 → KAGARI自身の改善で、同梱ソースを作業先にした専用タスクを開きます。希望する変更を入力して実行してください。Codexではworkspace-write、Claude CodeではEditとWriteを許可します。UIには ui/Main.xaml と ui/Desktop.cs、Rustコアには src 以下を使用します。起動中の配布版を更新する場合は、別フォルダーにソースをコピーして build-ui.ps1 でビルドし、そのフォルダーの KAGARI.exe で確認します。

## タスク・KPI履歴の復元点

旧形式のタスクID・セッション所有者を移行するときは、書き換え前の `workspace.tsv` と `kpi-history` 内の観測JSONを、同じ保存フォルダーの `restore-points\日時-識別子` に保存します。JSONには観測値と改善策メモが含まれます。復元点の作成に失敗すると移行は停止します。対象はタスクとKPI履歴で、CLIの会話本文や画像ファイルは別保管です。

復元にはソース同梱のスクリプトを使います。次のコマンドで復元点と新しい出力フォルダーを指定してください。マニフェストのSHA-256と照合し、欠落・破損があればファイル名を表示して停止します。

```powershell
.\src\recovery.ps1 -Mode Restore -Source 'D:\保存先\restore-points\日時-識別子' -Destination 'D:\復元確認\新しいフォルダー'
```

現在の保存データを一時フォルダーでバックアップ・復元し、全ファイルを元のコピーと照合するには、次のコマンドを使います。

```powershell
.\tests\verify-recovery.ps1 -SourceDirectory (Join-Path $env:LOCALAPPDATA 'RustAIWorkspace')
```

## AIニュース

左サイドバーの「AIニュース」（実行メニューからも表示可）を開き、収集担当に muse または dots を選びます。初期の登録ソースは指定の YouTube 4チャンネルです。URL を1行ずつ編集して「設定を保存」できます。

既定の「dots」で「Dotsで収集（DM）」を押すと、既存のクラウド版Dotsへ登録URLと収集依頼をSlackのDMで送ります。AIニュース画面を開いている間は返信を自動確認し、記事が届いた時点で取り込みます。返信待ちは再起動後も続きます。「Dotsの返信を確認」で手動確認、「返信の確認を終了」で待機を終了できます。Slack連携にはKAGARIで利用しているBotのDM送信・履歴閲覧権限が必要です。

「依頼をコピー」で登録URLを含む依頼を担当に渡し、返ってきた JSON をコピーして、同じ担当を選んで「結果JSONを取り込む」を押します。担当環境に対応する HTTPS API がある場合は、担当別の接続先を登録して「収集する」で直接依頼できます。API は POST で collector、sources、instruction、response_example を受け取り、items 配列を返します。各記事には title、summary、significance、url、source を含めます。source は登録URL、一般ニュース検索では空文字です。

記事を選ぶと要約・重要な理由・出典・収集担当を表示します。「原文を開く」で出典を確認できます。同じ原文URLの再取込は記事を更新します。「タスク化…」は選択中のプロジェクトに記事を引き継いだ編集画面を開き、保存すると作業キューに登録されます。
