# Codex実装指示：生成AI案件画面

## 優先順位
P0: 一覧・詳細分離、巡回状態の分離、連打対策、検索・ピン維持。
P1: フィルター、未確認管理、報酬表記統一、サイト別巡回明細。
P2: スキル抽出・適合度（根拠を表示できる場合のみ）。

## レイアウト
- 既存シェルは変更しない。画面内余白24 DIP、セクション間16、内部8～16。
- 上部にタイトル、今すぐ巡回、巡回状況。巡回設定は折りたたみ。
- KPIは全案件、新着、ピン留め。クリックで対応フィルターへ切替。
- 検索、サイト、報酬形態、稼働条件、並び替え。未取得値を独立した選択肢にする。
- 一覧は左約68%、詳細は右約32%。GridSplitterで変更可能。幅1100 DIP未満では詳細を別ペインまたはオーバーレイにする。行高72 DIP、見出し36。文字14～16 DIP、タイトル24。長文を一覧に展開しない。
- 行選択で詳細更新、ピン操作で行選択や外部遷移を発生させない。詳細には元の案件名、サイト、収集日時、金額、期限、稼働、仕事内容全文、掲載元リンク。省略は一覧表示だけ。
- DataGrid/ListViewは仮想化を有効にし、一覧と詳細で独立スクロール。外部リンクはHTTP/HTTPSのみ許容。

## 状態設計
公開巡回とDotsを別々に持つ。公開巡回: 未実行／実行中／完了／部分失敗／失敗。Dots: 未依頼／返信待ち／受信／タイムアウト／失敗。タイムアウトは既存設定に従い再確認を許可する。返信なしを成功扱いしない。
- 巡回対象数、確認済数、取得件数、最終更新日時、サイト別結果を別の値として管理する。
- 進行中の再クリックは既存run IDに紐付けるか無効化。同時実行しない。状態更新はUIスレッドへディスパッチし、finallyでボタン状態を復元。公開結果を先に反映しDots待ちで一覧をブロックしない。
- 案件の一意キーはサイト＋掲載ID、なければ正規化URL。再巡回でピン・確認済を失わない。既存永続化と互換性維持。
- 報酬は月額／固定／時給／見積り／不明を区別。月額上限を確定収入と扱わず、異なる報酬形態を単純比較しない。期限未取得は未取得と表記する。
- 未確認は詳細を開いたとき確認済みにする案。新着は前回成功した巡回以降の新規案件と定義する案。既存定義があれば優先し差異を報告する。

## WPF組み込み
JobsResources.xaml を既存ResourceDictionaryにMergedDictionariesで追加し、Path Data="{StaticResource Jobs.Icon.pin}" Style="{StaticResource Jobs.IconPath}" のように利用する。SVGは他UI用。既存MVVMのViewModel・Commandを再利用し、新規モデルへの全面置換は避ける。既存テーマに合わせてBrushを調整可。アイコンのみの操作にはToolTipとAutomationProperties.Nameを付与し、キーボードでも操作可能にする。

## 受入条件
- 1280×720、1600×960、1920×1080および125/150% DPIで主要操作に到達できる。
- 検索・絞り込み・並び替え・ピンが併用でき、0件時も理由と解除操作を表示。
- 1000件で一覧が仮想化され、巡回中もスクロール・選択可能。
- 巡回連打で処理重複せず、Dots返信0件でも公開案件が表示される。
- サイト失敗・タイムアウト・キャンセルでも永久に「確認しています」にならない。
- 更新前後で案件数・重複・ピン状態・掲載元リンクを検証。
- 元案件の全文と金額・期限が保持され、欠損を推測で補完しない。
- 実装後に画面キャプチャ、変更ファイル、テスト結果、未解決事項を報告する。
