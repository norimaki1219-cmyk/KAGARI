# SHIRANUI アラート画面 UI 改善提案

## 1. 元画面で確認した事項

- 暗いグローバルナビ、プロジェクト表示、監視状態、4つのKPI、アラート履歴・判断 / ログ・統計のタブがある。
- KPIは「履歴アラート 200件」「未対応 195件」「高優先度 1件」「最終検知が過去24時間 110件」。これらは撮影時点の表示値であり、現在値ではない。
- 一覧は日時、プロセス、検知ルール、重要度、発生回数、対応状態、IDを表示。
- 詳細領域は検知理由、実行ファイル、プロセス起動経路のグラフ、問題なし・要確認などの判断がある。
- 選択された例は `powershell.exe` の `encoded_shell`、スコア65、未対応。元画面の記述ではエンコード指定は正常運用でも発生し得る。

## 2. 主な改善点

| 領域 | 現状の課題 | 改善案 |
|---|---|---|
| 情報階層 | ヘッダー・項目・表が小さく密集 | タイトル、KPI、フィルタ、一覧、詳細の順に視線誘導 |
| 一覧 | 表の幅が狭く、右側の空白が目立つ | 左右2ペインを画面幅で柔軟に配分 |
| 判断操作 | ボタンと選択行の関係が把握しづらい | 選択ID・対象名・重要度・判断ボタンを詳細先頭に集約 |
| 検知優先度 | 文字だけで優先度が見分けづらい | 重要度をアクセシブルな文字入りバッジで強調 |
| 検知理由 | 重要な文が他の項目に埋もれる | 理由の説明カード＋誤検知の可能性を注記 |
| フィルタ | 多数の小さなドロップダウン | 検索と重要度・状態・期間に集約し、クリアを用意 |
| プロセス経路 | 横に長いグラフが読みづらい | 背景とノードを整理し、実装時はパン・ズーム・全体表示を保持 |
| 運用状態 | 監視稼働と更新時刻の関係が弱い | ヘッダーの「監視中」と最終更新時刻を明示 |

## 3. 情報設計

- **最上段:** プロダクト、現在の画面、監視状態、更新操作。
- **KPI:** 200 / 195 / 1 / 110 の4指標を保持。クリックで絞り込みの入口にする。
- **操作領域:** テキスト検索、重要度、対応状態、期間、未対応のみ。
- **一覧:** 重要度、プロセス、検知ルール、発生回数、対応状態を見ながら行選択。時刻は省略表示、完全な日時は詳細。
- **詳細:** 検知理由 → 判断 → ルール・日時 → パス → 起動経路。
- **集計:** ログ・統計タブに分離。

## 4. 表示・UXルール

1. 高・緊急は赤、注意は琥珀、低は中立色。色のみで区別せず必ずテキストを併記。
2. 「検知スコア」は独自スコアであり、悪性と確定する値として表示しない。
3. 「問題なし」「要確認」は選択中アラートIDにのみ作用させ、操作前の対象を明示。重要度の高い判定変更は確認ダイアログや監査履歴を検討。
4. 同一アラートへの重複判定は冪等化し、データ更新時の競合をAPI側で扱う。
5. フィルタの件数はバックエンドの集計値を使う。UIデモでの「200件中サンプル表示」は実一覧件数ではない。
6. ステータス、読み込み中、取得失敗、権限なし、空検索結果の各状態を実装。
7. 表はキーボードで行選択可能にし、重要な操作はキーボードフォーカス表示を保証。
8. 画面が狭い場合は一覧と詳細を縦に積む。実製品では詳細ドロワーも検討。
9. 稼働状態、更新日時、アラートの検知日時は別の概念として表示。
10. プロセスグラフは記録されたノード・エッジだけを表示し、情報が不明な箇所を推測で補わない。

## 5. 実装優先度

- **P0:** レイアウト・文字可読性・選択行の明確化・安全な判定導線・API整合。
- **P1:** 検索/フィルタ統合・件数連動・状態表示・キーボード操作・レスポンシブ。
- **P2:** 起動経路グラフのズーム操作、フィルタ保存、分析用グラフ、ショートカット。

## 6. 画面の最小寸法（目安）

- サイドバー: 68px、トップバー: 64px、コンテンツ余白: 28px。
- 詳細ペイン推奨最小幅: 390px。アラート一覧の推奨最小幅: 500px。
- カード角丸: 12px、コントロール角丸: 8px、最小クリック領域の目安: 40px。
- 本文13px、表12px、見出し15〜24px、KPI29px。ユーザーの文字サイズ設定に追従。

## 7. デザイン意図

既存のSHIRANUIらしい濃紺・青緑を維持し、画面全体は明るい背景にして確認作業の視認性を高める。危険度が高い項目にのみ赤を使い、通常の注意は穏やかな琥珀色で扱う。Windowsデスクトップに馴染む軽量なフラットUI。
