# Codex / Claude Code 実装引き継ぎ指示

## 目標

添付スクリーンショットの SHIRANUI アラート履歴・判断画面を、`index.html` の構成と `assets/design-tokens.json` のデザイン定義を参考に改善する。**既存機能・API・データモデルは壊さず、UI差分を段階的に実装する。**

## 前提

- HTMLはUI挙動のデモで、WPF XAMLへの自動変換前提ではない。
- アイコンは単色SVG。WPFならSVG対応ライブラリ導入可否を確認し、困難ならGeometry/PathまたはPNGに変換して使用する。
- Rust側のセキュリティ判定機能や実プロセス情報を本モックのデータで置き換えてはならない。

## 実装タスク

1. 現在の画面実装を確認して、既存のアラート取得API、判定API、キュー操作、フィルタ、期間指定、グラフ描画コンポーネントを洗い出す。
2. 既存の画面構造を「タイトル + 監視状態」「4 KPI」「タブ」「検索フィルタ」「一覧・詳細の2ペイン」に再配置。
3. `design-tokens.json`をリソース辞書（色、フォント、余白）にマッピングする。
4. SVGを各コマンドアイコンへ割り当てる。キーボード操作、ツールチップ、アクセシブル名も付与。
5. 一覧選択に応じて詳細をバインド。選択解除、フィルタでの消失、ローディング状態も処理。
6. 問題なし・要確認などの判断更新は、対象IDとリビジョンを送る。完了後のみ画面更新。失敗は明示し、監査記録との整合を守る。
7. 作業キュー追加、パスコピー、表示更新、CSV保存、ログ統計切替は既存の動作を維持。
8. プロセスツリーは記録外・起動記録範囲外などの表現を既存仕様から維持し、実際のノード・エッジのみを描画。
9. 通常幅 / 1280px / 1024px / 拡大率125〜200%でUIが破綻しないことを確認。

## 受け入れ基準

- 未対応件数、重要度別件数、期間内件数がバックエンド表示と一致。
- 表で選択したIDと、判断対象IDが常に一致。
- 判定操作に成功/失敗の応答があり、失敗時に成功扱いしない。
- フィルタ・ソート・更新後も、ユーザーが対象を誤認しない。
- 画面幅が不足しても重要操作が隠れて実行不能にならない。
- 警告色の使い分けに意味があり、色弱の利用者にも識別可能。
- 本番画面にデモの仮グラフ、ダミー検知、固定集計値を残さない。

## 変更を避けること

- SHIRANUIの検知閾値、ルール、アラートID採番、Rust判定ロジック。
- セキュリティイベントの重要度をUIだけの判断で自動変更すること。
- 未記録の親子プロセスを推測してツリーに描画すること。
